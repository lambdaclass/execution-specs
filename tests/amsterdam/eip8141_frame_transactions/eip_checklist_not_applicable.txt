blob_count_changes = EIP-8141 reuses the EIP-4844/7594 blob limits unchanged, which the blob composition tests exercise as composition rather than as changed counts.
execution_layer_request = EIP-8141 does not introduce an execution layer request.
block_level_constraint = EIP-8141 constrains transactions rather than blocks; a frame transaction's derived gas limit is charged to the ordinary block gas pool, which the block-interaction tests pin under the transaction type.
transaction_type/test/fork_transition/before = the repository exposes EIP-8141 through the pseudo Bogota fork built on the Amsterdam spec module, and no transition fork exists, so a pre-fork rejection fixture cannot be filled.
transaction_type/test/contract_creation = a frame transaction has no creation form since a null frame target resolves to the sender rather than to creation, and deployment happens by calling a factory, which the deploy-then-use test covers.
transaction_type/test/intrinsic_validity/to = a frame transaction has no `to` field at all; the per-frame target replaces it and its null form resolves to the sender, which the target resolution tests pin.
transaction_type/test/intrinsic_validity/gas_limit = a frame transaction carries no gas limit field, so no value can be supplied for one; the derived limit is the intrinsic cost plus the frame gas limits, which places it at or above the intrinsic cost by construction, and the exact and exact-minus-one boundary is instead pinned per frame by test_frame_oog_isolation.
transaction_type/test/signature/invalid/r/max = an `r` of 2**256 does not fit the entry's fixed sixty-five byte secp256k1 signature, so such an entry is rejected on its length rather than on its component value, which the signature length arms pin.
transaction_type/test/signature/invalid/s/max = an `s` of 2**256 does not fit the entry's fixed sixty-five byte secp256k1 signature, so such an entry is rejected on its length rather than on its component value, which the signature length arms pin.
transaction_type/test/tx_scoped_attributes/persistent/reset = the frame-scoped attributes are unreadable outside a frame transaction because every new instruction halts there, so no value survives into a later transaction to be reset.
transaction_type/test/block_interactions/single_tx/valid = the EIP-7825 per-transaction gas cap is far below any block gas limit used here, so a derived transaction gas limit equal to the block gas limit is unreachable; the cap boundary is pinned instead.
new_transaction_validity_constraint/test/fork_transition = Bogota has no transition fork, so activation-boundary arms for the new validity constraints cannot be filled.
modified_transaction_validity_constraint/test/fork_transition = Bogota has no transition fork; the EIP-3607 exemption is instead pinned same-fork by accepting a type-6 and rejecting a type-2 from the same code-bearing account.
opcode/test/fork_transition = Bogota has no transition fork; the opcodes' unavailability outside their context is pinned same-fork by executing them in type-0/2/4 transactions instead.
opcode/test/data_portion = none of APPROVE, TXPARAM, FRAMEDATALOAD, FRAMEDATACOPY, FRAMEPARAM or SIGPARAM carries an immediate data portion.
opcode/test/stack_overflow = every new opcode pops at least as many stack items as it pushes, so no execution can grow the stack past its height at entry.
opcode/test/stack_complex_operations = the new opcodes use plain pop/push access with no data-portion variables or unusual stack addressing.
opcode/test/contract_creation = the new opcodes do not create contracts.
opcode/test/terminating/rollback = APPROVE terminates its call frame successfully like RETURN so there is nothing to roll back, and the other opcodes terminate only via exceptional halts covered by the halt tests.
opcode/test/return_data/buffer/current = the new opcodes never read the return-data buffer; APPROVE only writes it for the parent, which the return-data test pins.
opcode/test/execution_context/staticcall/ban_check = none of the new opcodes writes code, storage or balance, so no static-context ban applies to them.
opcode/test/execution_context/staticcall/ban_no_modification = the new opcodes are not banned from static contexts at all; APPROVE is the one state-affecting instruction a VERIFY frame's static call may run, which the verify-frame restriction test pins.
opcode/test/execution_context/staticcall/sub_calls = there is no static-context ban on the new opcodes to propagate into sub-calls.
opcode/test/execution_context/delegatecall/storage = none of the new opcodes modifies storage.
opcode/test/execution_context/delegatecall/balance = none of the new opcodes modifies a balance.
opcode/test/execution_context/delegatecall/code = none of the new opcodes modifies code.
opcode/test/execution_context/initcode/behavior/tx = a frame transaction has no contract-creating form, and in older transaction types the new instructions halt rather than execute, which test_opcodes_undefined_in_other_tx_types pins.
opcode/test/execution_context/initcode/reentry = the new instructions read transaction-static data and the executing frame's index, so repeating the same initcode at the same address cannot change what they return.
opcode/test/execution_context/block_context = none of the new opcodes reads a block property, so no block field can change their behavior.
opcode/test/gas_usage/order_of_operations = the new opcodes charge no operation-dependent stipend: the introspection reads are flat constants, and the only variable term is FRAMEDATACOPY's word and memory expansion, whose exact and out-of-gas boundaries the copy gas tests pin.
system_contract/test/contract_substitution = the spec licenses clients to shortcut the expiry verifier only when observably identical and itself warns that substituted code is implementation-divergent territory, so substituted-code behavior is deliberately left unpinned.
system_contract/test/contract_variations/networks = only the canonical runtime code at the expiry verifier address is normative; per-network variations are the same implementation-divergent territory the spec warns about.
system_contract/test/deployment/missing = clients must install the expiry verifier at activation and the filler injects it into genesis, so a missing-predeploy chain is not constructible as a fixture.

system_contract/test/out_of_bounds = every value of the eight-byte input domain is a valid timestamp by construction.
